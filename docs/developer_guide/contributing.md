# Contributing to Bible-AI

Thank you for your interest in contributing to Bible-AI! This document provides guidelines and instructions for contributing to the project.

## Code of Conduct

By participating in this project, you agree to abide by our Code of Conduct. Please read it before contributing.

## How to Contribute

### Reporting Bugs

1. Check if the bug has already been reported in the [Issues](https://github.com/ravikumarkatta/bible-ai/issues).
2. If not, create a new issue with a descriptive title and clear description.
3. Include steps to reproduce, expected behavior, actual behavior, and environment details.
4. Attach screenshots if applicable.

### Suggesting Enhancements

1. Check if the enhancement has already been suggested in the [Issues](https://github.com/ravikumarkatta/bible-ai/issues).
2. If not, create a new issue with a descriptive title and clear description.
3. Explain why this enhancement would be useful to most Bible-AI users.
4. Suggest an implementation approach if possible.

### Pull Requests

1. Fork the repository and create a new branch for your feature or bugfix.
2. Follow the coding style and standards used in the project.
3. Write tests for your changes.
4. Ensure all tests pass and the application runs correctly.
5. Submit a pull request with a clear description of the changes.

## Development Setup

Follow the setup instructions in the project README.md to get your development environment running.

## Coding Standards

### Python Code

- Follow PEP 8 style guide.
- Use type hints where appropriate.
- Document functions and classes with docstrings.
- Keep functions focused and small.

### JavaScript/React Code

- Use ESLint with the project's configuration.
- Follow the React components structure established in the project.
- Use functional components with hooks where appropriate.
- Document complex logic with comments.

### Testing

- Write unit tests for all new functionality.
- Ensure theological validation tests cover diverse theological scenarios.
- Maintain test coverage for critical components.

## Theological Contributions

When contributing theological content or validation rules:

1. Clearly document scriptural basis for any theological statements.
2. Be respectful of different denominational perspectives.
3. Provide references for theological claims.
4. Follow the theological basis document guidelines.

## Documentation

- Keep documentation up-to-date with code changes.
- Use clear, concise language.
- Provide examples where helpful.
- Update API documentation for any interface changes.

## Review Process

1. All pull requests require review from at least one project maintainer.
2. Theological changes may require additional review from theological contributors.
3. Address all review comments before merging.
4. Be respectful and constructive in code reviews.

## License

By contributing to Bible-AI, you agree that your contributions will be licensed under the project's MIT License.

## Questions?

If you have any questions about contributing, feel free to open an issue for discussion.

Thank you for contributing to Bible-AI!
